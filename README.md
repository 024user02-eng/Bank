SRS Structure for Bank Customer Details
Introduction
Purpose: Define user requirements for managing customer data in the banking system.
Scope: Describe the module for storing, updating, and viewing customer information.
Overall Description
Product Functions: Register, modify, search, and delete customer records.
User Characteristics: Bank employees (staff) and customers.
Functional Requirements (Customer Details Module)
Customer Registration (KYC): Capture name, address, contact details, identification docs, and date of birth.
Data Validation: Ensure uniqueness of customer ID, valid phone/email formats, and mandatory fields.
Account Linking: Link customer details to specific account types (Savings, Checking, Loan).
Profile Management: Allow authorized employees to update address, phone number, or KYC status.
View Account Details: Display balance, history, and personal details via secure login.
Non-Functional Requirements
Security: Data encryption for personal information, secure authentication.
Privacy: Adherence to regulatory guidelines for handling sensitive personal data.
Usability: Intuitive interface for easy data entry.
External Interface Requirements
User Interface: Web or mobile application for user access.
Database: Secure backend database to store customer records.
